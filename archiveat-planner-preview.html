01 · Overview

시스템의 성격과 목적

Archiveat Planner는 아카이빗의 콘텐츠 자산을 고객에게 적합한 상품과 제안으로 전환하여, 클래스·쿠킹박스·케이터링 매출을 높이기 위한 프론트엔드 서비스 OS입니다.

05 · Menu Master DB

Content Card & 메뉴 Master DB

메뉴 하나를 하나의 콘텐츠 자산으로 관리하되, 카테고리·계절·대상·수업 방식·상품화 상태를 여러 태그로 연결합니다. 이 DB가 메뉴 추천, 클래스, 쿠킹박스, 몰 상품, 기업 제안과 마케팅의 공통 기반이 됩니다.

현재 원본 데이터 기준

원본 파일
카테고리마스터 v22
카테고리
19개
메뉴 등록 건수
465건
고유 메뉴
456개
총 메뉴 수의 기준
원본에는 메뉴가 입력된 472행이 있으며, 이 중 ‘신규 메뉴 입력’ 안내 행 7개를 제외하면 카테고리 등록 건수는 465건입니다. 서로 다른 카테고리에 중복 등록된 메뉴 9건을 하나의 메뉴 ID로 통합하면, 현재 관리할 고유 메뉴 수는 456개입니다. 따라서 대외·내부 보고에서 ‘총 메뉴 수’는 456개, ‘카테고리 배치 건수’는 465건으로 구분합니다.

중복 메뉴 처리 원칙

동일 메뉴가 여러 카테고리에 들어간 경우 삭제하지 않습니다. 하나의 메뉴 ID를 만들고 여러 카테고리 태그를 연결합니다. 현재 교차 등록된 메뉴는 쫄면, 히야시츄카, 탕반가릿국, 버팔로윙, 삼색달걀말이, 쇼유치킨, 아귀캐슈너트강정, 태국식달걀튀김, 그래놀라와과일콩포트입니다.

예: MENU-0128 히야시츄카 → 주 카테고리: 면·파스타·국수 / 추가 태그: 세계음식·일본·여름

쿠킹박스 및 등록 상태의 기준

항목정의DB 적용 원칙
쿠킹박스 가능 현재 보유한 456개 고유 메뉴는 모두 쿠킹박스 제작이 가능한 레시피입니다. 기본값을 ‘가능’으로 두고, 일정·수급·대량 생산·배송 조건만 개별 검토합니다.
등록 쿠킹박스로 상품화하여 아카이빗몰에 업로드한 상태입니다. 상품화 상태와 몰 업로드 상태를 의미합니다.
미등록 레시피 자산은 있으나 현재 아카이빗몰 상품으로 업로드하지 않은 상태입니다. 고객 제안은 가능하며, 선택 시 신규 상품화 작업을 진행합니다.
등록(미진열) 상품화·업로드는 완료했으나 현재 몰에서 노출하지 않는 상태입니다. 추후 DB에서는 상품화 상태와 진열 상태를 별도 필드로 분리합니다.

‘종류’ 문구의 의미: 메뉴 개발 출처와 시기

종류개발 배경현재 보유 자산
베이직 아카이빗몰 런칭 전, 전문가들이 기본 활용도가 높은 메뉴로 선정한 레시피 레시피·구성품·사진·영상 일부
마스터 아카이빗몰 런칭 전, 전문가들이 본인의 시그니처 메뉴로 선정한 레시피 레시피·구성품·사진·영상 일부
쿠킹박스 아카이빗몰 런칭 전, 쿠킹박스 활용을 전제로 미리 개발한 레시피군 레시피·구성품·사진·영상 일부
아카이빗 아카이빗몰 오픈 이후 아카이빗 내부에서 새로 개발한 메뉴 메뉴별 보유 자료를 확인하여 연결
갤러리아·경기도지식 등 외부 기업·기관과의 협업 및 제휴 클래스를 위해 개발한 메뉴 협업 과정개요·레시피·운영자료 등 프로젝트별 자산
관리 원칙
기존 ‘종류’ 값은 원본 이력을 보존하기 위해 유지합니다. 향후에는 ‘개발 출처(전문가·내부·외부 협업)’, ‘세부 프로젝트’, ‘개발 시기’, ‘보유 자산’, ‘상품화 상태’를 별도 필드로 분리하여 검색과 추천에 활용합니다.

10 · Next Action

현재 단계의 실행 우선순위

골격 설계는 완료되었습니다. 다음 단계는 전체 시스템을 더 꾸미는 것이 아니라, 현재 보유한 456개 고유 메뉴로 실제 고객 문의 한 건을 추천부터 제안서까지 처리하는 MVP를 실행하는 것입니다.

우선순위 1
메뉴 Master DB 기초 생성
456개 메뉴 ID, 465개 카테고리 관계, 종류·전문가·등록 상태를 우선 이관합니다.
우선순위 2
최소 추천 태그 입력
월·계절, 연령대, 직업·생활유형, 온라인·오프라인, 수업시간, 가격대, 배송 안정성만 먼저 입력합니다.
우선순위 3
첫 고객 문의 실전 테스트
고객 조건으로 내부 후보 10개를 추출하고 고객 발송용 5개 제안서를 만듭니다.
우선순위 4
선택 메뉴만 상세화
고객이 선택한 메뉴에 한해 구성품, 과정개요서, 원가, 견적과 운영 일정을 완성합니다.
실행 원칙: 모든 데이터를 완벽하게 만든 뒤 영업을 시작하지 않습니다. 실제 업체 요청을 처리하면서 필요한 필드와 평가 기준을 추가하고, 확정된 정의는 본 파일에 계속 누적합니다.
